# Spliceloom website

Static site (landing page, documentation, official skills) generated by a small Node.js script.
No framework and no runtime dependencies; fonts (Geist, Geist Mono — SIL OFL) are self-hosted.

```sh
npm run build                                   # the site imports the compiled Splice packages
npm run site:build                              # → apps/site/dist (reads the production registry)
npm run site:serve                              # preview at http://127.0.0.1:4321

node apps/site/build.ts --registry http://127.0.0.1:8787 --site-url https://example.test
node apps/site/build.ts --snapshot apps/site/dist/data/registry.json   # rebuild offline from earlier data
```

## Structure

| File | Role |
| --- | --- |
| `build.ts` | Documentation information architecture (`DOC_NAV`), page generation, search index, sitemap |
| `src/pages.ts` | Landing page, documentation layout, 404 |
| `src/registry.ts` | Official skills from the registry API, verified like `splice verify` |
| `src/providers.ts` | Providers from the data layer's own registry (verified ones only) |
| `src/markdown.ts` | Safe Markdown renderer for `docs/*.md` and `SKILL.md` |
| `public/styles.css`, `public/app.js` | Design system; hero video, menu, terminal replay, docs search, drawer, live registry refresh |
| `public/media/` | Hero video (1600/960 px H.264, no audio) and poster; licensed stock footage, see `CREDITS.md` |

The hero video loads after the page, never under `prefers-reduced-motion` or Save-Data (the poster
is shown instead), uses the smaller file on narrow screens and pauses off screen.

## Data flow

```
build.ts → src/registry.ts  → public registry API (GET /packages/…) → D1 metadata
                            → verifyPackage (download, SHA-256, size, package, metadata, provenance)
         → src/providers.ts → @spliceloom/data provider registry (names, kinds, capabilities)
browser  → assets/app.js    → public registry API (CORS) → live versions; in-browser SHA-256 check
                            → assets/search-index.json → documentation search
```

- Official skills: name, description, version, permissions, tools and verification come from the
  registry. `@splice/web`, `@splice/market` and `@splice/onchain` are shown once the registry serves
  them. If the registry cannot be read, the build fails instead of inventing data.
- Figures on the landing page (skills, providers, capabilities) are counted from that data and the
  code; there are no user, download or customer numbers.
- The terminal replays the real CLI output; the version and SHA-256 shown are the registry's.

## Security

- Only public registry metadata reaches the site; no tokens, environment variables or admin
  endpoints (tests scan the output).
- Every page sets a Content Security Policy: scripts, styles and fonts from the site only, network
  access only to the registry origin. `frame-ancestors` must be sent as an HTTP header by the host.
- No cookies, no analytics, no third-party requests.

## Hosting

The output is plain static files. It is **not deployed** and no custom domain is configured.

URLs are clean: pages are written as `docs/getting-started.html` but linked as `docs/getting-started`
(no `.html`, no `#`). The host must serve `x.html` for `/x` — Cloudflare Pages, Vercel (`cleanUrls`)
and Netlify do; `npm run site:serve` does the same and redirects `*.html` to the clean URL. Links to
a section carry `data-section="id"`; `app.js` scrolls there without a fragment in the address bar, and
strips the fragment from old `#…` links after scrolling.
`--site-url` (default `https://spliceloom.com`) only sets canonical, Open Graph and sitemap URLs.
Planned origins: `spliceloom.com` (this site), `docs.spliceloom.com` (today `/docs`),
`registry.spliceloom.com` (today the workers.dev registry), `app.spliceloom.com` (dashboard).
